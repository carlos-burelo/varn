# JIT On-Stack Replacement — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:executing-plans` (or `superpowers:subagent-driven-development`) to work this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Let a function that is entered **once** and then loops be compiled *while it is still running*, so the back-edge tier threshold can be raised from 1 to 128. That removes ~2.3x of wasted Cranelift work from every short-running program without giving up any hot-loop speed.

**Architecture:** `varn-jit::compile` gains an optional `osr_ip`. In OSR mode it lowers the *same* function body but emits a parameterless prologue that reloads every register from the VM frame at `base` and jumps straight to the CLIF block for `osr_ip` instead of block 0. `varn-vm` counts back edges in `OpCode::Loop`, and when a proto proves hot mid-frame it returns `ControlCallFlow::ContinueFrame` with an OSR request that the frame loop services through the existing `execute_jit_frame`.

**Tech Stack:** Rust, cranelift-codegen (the existing `clif` lowering), `varn-vm` interpreter dispatch, `varn-types::FunctionProto`.

## 1. Why — measured, not assumed

`crates/varn-vm/src/frame.rs:316` sets `JIT_TIER_THRESHOLD = 1` for any proto with a back edge, and says why in its own comment: *"it may never be entered twice and there is no OSR to rescue it."* Every function containing a loop therefore pays ~2 ms of Cranelift on its **first** entry, however short the loop.

Measured on this machine (release, best-of-5 wall clock, `VARN_JIT_TIER` overrides the back-edge arm):

|---|---|---|

## 3. The correctness hazard — read this before writing any code

`crates/varn-jit/src/clif/alloc.rs:312` documents it on `reload_boxed`:

> The restored representation is the EXACT inverse of the one `store_home` used — both driven by **the flow's kind state, never by `register_meta`**. The two authorities disagree in real code (the meta types a slot `Int` while the flow has merged it to a boxed kind at a loop header, and vice versa); restoring by the meta then leaves a raw integer in a register the lowering goes on to read as boxed `VmValue` bits, which reinterprets a small int as a denormal float — silently wrong comparisons, and **an infinite loop when it is a loop counter**.

This is precisely the OSR situation:

- The interpreter's frame slots always hold **boxed `VmValue`**.
- The CLIF block at `osr_ip` expects whatever `entries[&osr_ip]` says — some registers unboxed `i64`, some raw `f64`, some boxed.

So the OSR prologue **must** convert using `entries[&osr_ip]` (the `kind_flow` result), not `register_meta`. `kind_flow` returns `HashMap<usize, Vec<K>>` keyed by block-start ip (`crates/varn-jit/src/clif/kinds.rs:256`), and `lower.rs:578` already computes it as `entries`. Feed `entries[&osr_ip]` to the reload as its `state`.

Getting this wrong compiles cleanly, passes trivial tests, and hangs on a loop with an unboxed counter. **Task 3's test exists specifically to catch it.**

## 5. Eligibility guards — refuse OSR when any holds

An OSR entry abandons the interpreter frame mid-execution. It is only sound when the frame carries no interpreter-side state the compiled body does not model:

1. **Active `try` handler in this frame.** Compiled code does not know about the interpreter's handler stack.
2. **Generator or async proto.** `Await`/`Yield` need the outermost frame's suspension buffer; an OSR frame is not the outermost.
3. **Not frame-aware.** OSR needs `base`; a non-frame-aware signature has no frame.
4. **`osr_ip` is not in `block_starts`.** Only a real block can be jumped to. (A `Loop` target always is — assert rather than silently skip, so a future encoding change is caught.)
5. **`proto.chunk.code.len() > SIZE_GATE_WORDS`.** Same gate as normal compilation, same reason (nested clif frames are not resumable).
6. **`jit_osr_failed` already set,** or the proto already has an OSR entry for a *different* ip — compile one OSR variant per proto, first hot loop wins.

```rust
// crates/varn-jit/src/clif/osr.rs
/// Materialize every register from its `ctx.stack` home slot into the
/// representation the OSR target block expects, then jump there.
///
/// The interpreter's frame always holds boxed `VmValue`. The block at
/// `osr_ip` expects `entries[&osr_ip]`. Converting by `register_meta`
/// instead would leave raw ints where the lowering reads boxed bits — see
/// the warning on `alloc::reload_boxed`.
pub(super) fn emit_osr_entry(
    b: &mut FunctionBuilder,
    actx: &AllocCtx,
    target_state: &[K],
    target: cranelift_codegen::ir::Block,
) {
    let all: Vec<usize> = (0..actx.nregs).collect();
    alloc::reload_boxed(b, actx, target_state, &all);
    b.ins().jump(target, &[]);
}
```

- [ ] **Step 5: Bail cleanly.** If `blocks` has no entry for `osr_ip`, or `entries` has none, return `Err("osr: target ip is not a block start")` so the caller records `jit_osr_failed` instead of panicking.

## 6. Validation protocol

Measurement on this machine is **noisy enough to invert a 40% effect** — a single A/B is worthless. During this work an unpaired run reported a 46% regression that a properly paired 9-round sample resolved to 7%.

Rules:
- Always compare **two binaries alternately in one loop**, never sequentially in separate sessions.
- Use `--runs 30` and take the **median of ≥9 alternating rounds**.
- Keep an unchanged control benchmark in the mix; if the control moves between rounds, discard the batch.

Reproduce the reference numbers with these files (write them anywhere outside the repo):

```vn
// hotloop.vn — must stay ≈70 ms
function run(n: int): int { let s: int = 0
  for (let i: int = 0; i < n; i = i + 1) { s = s + (i % 7) }
  return s }
print(run(20000000))
```

```
# suite (target: 159 -> ~68 ms)
./target/release/vn.exe bench ./tests/main.vn --runs 30

# tier/OSR sweeps, no rebuild needed
VARN_JIT_TIER=<n> VARN_JIT_OSR=<n> ./target/release/vn.exe run <file>
```

## 8. Rollback

Every piece is additive except Task 6. If OSR proves unsound under some shape, revert **Task 6 only** (`JIT_TIER_THRESHOLD` back to 1): the OSR machinery then simply never pays off, and behaviour returns to today's. ## 9. Known follow-ups (do not do here)

- Escape analysis / scalar replacement for class instances — biggest remaining measured gap (2.37x on `alloc`).
- Array element representation (1.53x on `arr`).
- `const_fold` vs runtime divergence: `1.0 / 0.0` folds to `inf` at compile time but raises `division by zero` at runtime in **both** tiers. Violates the bit-exactness rule in CLAUDE.md; needs a semantics decision (IEEE `inf` vs error) before it can be fixed.
- Bitwise ops are typed `Dynamic` even for proven-`int` operands (`bor.dyn`), so there are no typed bitwise opcodes and `passes::algebraic` cannot touch them. Contradicts `<backend_principle>`.
